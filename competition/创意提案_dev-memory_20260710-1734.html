01 / Creative Intro

创意介绍

从真实开发痛点出发，用一个轻量 Skill 解决 AI 编程助手的"失忆"问题。

想解决的问题

AI 编程助手（TRAE、Cursor、Copilot）的对话记忆是短时记忆——每次对话结束后，本次开发中积累的实现思路、踩坑经验、架构决策等知识就消失了。下次对话又得从头探索，浪费大量算力和时间。

核心痛点：知识随对话消失

动机

在开发 kpl-dashboard 项目时发现：换一个新对话后，AI 不知道之前做了什么——不知道东方财富 API 的正确参数、不知道连板高度为什么要放右轴、不知道之前踩过的坑。重复探索浪费算力，重复踩坑浪费时间。

真实项目验证

产品形态

一个 TRAE Skill 技能，纯 Markdown 文件，零依赖。安装后对话结束时自动触发，提取六维开发记忆，保存到项目目录的 docs/dev-memory/ 下，随代码版本管理。

SKILL.md · 零依赖
02 / Target Users

目标用户及痛点

面向所有使用 AI 编程助手进行项目开发的开发者，尤其是跨对话、跨工具、跨协作者协作的场景。

!

新开对话 — AI"失忆"

AI 不知道之前做了什么，不了解项目当前状态、已做的决策、已踩的坑。每次新对话都要重新描述背景，重新探索方案。

!

换 AI 工具 — 记忆丢失

TRAE 内置 memory 是工具级记忆，存在 ~/.trae-cn/memory/。换到 Cursor、Copilot 后，所有项目记忆全部丢失，从零开始。

!

换协作者 — 上下文断裂

团队成员接手项目时，不知道之前的架构决策原因、踩过哪些坑、哪些方案尝试过又放弃了。口述或写文档容易遗漏关键细节。

!

调试问题 — 重复踩坑

同一个 API 参数错误、同一个环境配置问题，在不同对话中被反复遇到、反复调试。已解决过的坑没有沉淀，算力和时间白白浪费。

03 / Value & Impact

价值与意义

不仅是效率工具，更是知识资产——让开发记忆成为可传承、可版本化、可进化的项目资产。

效率提升

避免重复探索和重复踩坑。新对话开始时 AI 读取记忆文件，立即了解项目全貌，直接从上次的结论继续，不再从零开始。

节省算力 / 节省时间

知识传承

记忆文件保存在项目目录内，随 Git 版本管理。每一次决策、每一个踩坑、每一条结论都有时间戳记录，完整保留知识演进轨迹。

随项目走 / 随 Git 管

商业价值

作为 TRAE 生态 Skill 标配，可随项目分发。每个用 TRAE 开发的项目都能自带记忆，降低团队协作门槛，提升 TRAE 平台的用户粘性。

生态标配 / 平台粘性
04 / Core Features

核心特性

六大核心特性，构建从提取、存储、归档到自我进化的完整记忆闭环。

六维记忆提取
从对话上下文中自动提取六个维度的开发记忆：任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息。每个维度有明确的格式和提取规则。
6 dimensions · auto-extract
追加式演进
旧记忆永不删除，只追加更正说明。发现旧记忆有错误、矛盾或过时时，在"历史更正记录"中追加更正，完整保留知识演进轨迹。
append-only · never delete
零依赖
纯 Markdown 文件操作，不执行任何脚本，不依赖任何外部服务。换任何 AI 工具、任何编辑器都能读取，记忆跟着项目走。
0 deps · pure markdown
按周归档
主文件保持精简（每维保留 3-5 条），溢出的旧条目自动归档到按 ISO 周数命名的周文件。主文件始终反映最新状态，历史完整可溯。
ISO week · archive/YYYY-Www.md
自我进化
Skill 自身预留"迭代记录"区域，每次执行时检查是否遇到规则不足、边界情况、提取遗漏等问题，发现改进点则自动更新 SKILL.md 并记录版本。
self-evolving · v1.0 → v1.x
自动迁移
首次使用时，自动从 TRAE 内置 memory（~/.trae-cn/memory/）迁移已有项目记忆，按维度归类到六维记忆体系中，无需手动搬运。
auto-migrate from TRAE memory
05 / Six Dimensions

六维记忆维度

从六个互补维度完整覆盖一次开发会话中的关键知识，每条记忆精确到分钟。

01

任务摘要

Task & Changes

本次做了什么，1-3 句话概括核心变更。帮助新对话快速了解项目最新进展。

[2026-07-10 16:30] 完成7项看板优化：标题修改、涨停分布默认显示...
02

踩坑记录

Pitfalls & Fixes

遇到什么错误、根因是什么、如何修复。标注已解决或未解决，避免重复踩坑。

[2026-07-10 16:30] ✅ API返回rc=205 → 原因: 参数错误 → 修正: ut=7eea...
03

探索路径

Exploration Path

尝试了什么方案、为什么放弃或采纳。记录决策的思考过程，而非仅仅最终结果。

[2026-07-10 16:00] KPL API(不支持历史) → 东方财富(参数错误) → 修正后成功
04

最终结论

Conclusions & Best Practices

当前验证有效的结论和最佳实践。发现更好的结论时追加更正，旧结论保留不删。

[2026-07-10 16:30] 东方财富涨停池API正确参数: http + ut=7eea... + dpt=wz.ztzt
05

架构决策

Architecture Decisions

为什么选这个方案、放弃了什么、影响范围。让后续开发者理解决策背后的原因。

[2026-07-10 16:15] 连板高度放右轴(0-10) → 原因: 左轴数值过大导致不可见
06

环境信息

Environment & Dependencies

工具版本、API 地址、配置变更、数据库结构等环境信息。保障环境可复现。

[2026-07-10 16:30] 东方财富API: http://push2ex.eastmoney.com/getTopicZTPool
06 / Workflow

工作流程

对话结束时自动触发的 6 步执行流程，从读取到进化形成完整闭环。

01
读取
读取现有 DEV_MEMORY.md 和 SKILL.md 迭代记录
02
提取
从对话上下文提取六维记忆，加时间戳
03
对比
新旧记忆对比，发现矛盾/过时/错误则追加更正
04
写入
新条目插入各维度顶部，更新状态概览
05
归档
溢出条目移入按周归档文件，跨周先归档上周
06
进化
检查规则不足，自动改进 SKILL.md 并记录版本

07 / Comparison

与其他方案对比

dev-memory vs TRAE 内置 memory vs Notion vs Git commit — 四种方案各有取舍，dev-memory 在"随项目走 + 自动提取 + 零依赖"上优势突出。

对比维度 dev-memory TRAE 内置 memory Notion / Confluence Git commit message
P 随项目走
✓ 项目目录内，随 Git 管理 ✗ 工具级存储，换工具丢失 ✗ 独立平台，不随项目走 ✓ 随 Git 走
A 自动提取
✓ 对话结束自动触发 ~ 部分自动，需用户确认 ✗ 需手动维护 ✗ 需手动写
D 零依赖
✓ 纯 Markdown，零脚本 ✗ 依赖 TRAE 平台 ✗ 依赖平台账号和网络 ✓ 零依赖
T 记录思考过程
✓ 探索路径 + 架构决策 ~ 记录结论，少记过程 ✓ 可记录，需手动写 ✗ 仅记录代码变更
C 踩坑经验沉淀
✓ 独立维度，标注解决状态 ~ 散落在经验教训中 ✓ 可记录，需手动写 ✗ 不记录踩坑
E 自我进化
✓ Skill 自动改进迭代 ✗ 规则固定 ✗ 模板固定 ✗ 无
V 版本演进追踪
✓ 追加式更正，保留轨迹 ✗ 覆盖式更新 ~ 有版本历史 ✓ 有 commit 历史
