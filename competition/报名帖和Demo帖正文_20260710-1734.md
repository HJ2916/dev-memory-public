## 1. 创意名称 + 创意介绍

**dev-memory — 项目级 AI 记忆系统**

用 AI 编程助手开发项目时，每轮对话都在积累隐性知识：踩过的坑、验证过的方案、做过的架构取舍。但这些知识跟着对话上下文一起蒸发了——下次开新对话，AI 又从零开始，把走过的路重走一遍，把踩过的坑再踩一遍。

这不是个别体验。AI 行业发展至今，记忆系统并不新鲜，但所有方案都绑在特定载体上：ChatGPT 的 Memory 绑用户账号，Claude Code 的 CLAUDE.md 绑工具，Hermes Agent 的四层记忆绑框架。可现实是，AI 产品迭代极快，工具会换、账号会变，唯独你的设备和项目代码是稳定的锚点。

**dev-memory 做的事很简单：把开发记忆的归属权从账号和工具上拿下来，放到项目这一层。** 用纯 Markdown 文件存在项目目录里，跟着 Git 走，不绑任何平台。任何 AI 工具来了都能读，工具换了记忆还在。

灵感来自一个很具体的场景：我在开发一个数据分析项目时，前一轮对话花了大量时间排查某个第三方 API 的参数问题，终于调通。结果下一轮新对话，AI 又从头试错。那一刻意识到，AI 缺的不是能力，是记忆。而现有方案要么绑工具（Claude Code 最近还被曝出在代码中植入针对中国用户的检测逻辑，把记忆托付给单一海外平台风险不可控），要么太重（Hermes 需要完整框架）。我需要的是轻量的、工具无关的、随项目走的记忆。

dev-memory 的定位是：取 Claude Code 的"项目目录存储 + AI 自动维护"，取 Hermes 的"自我进化 + 迭代记录"，用纯 Markdown Skill 实现，不绑任何工具。一个 SKILL.md 文件就是全部，零脚本、零依赖、零外部服务。

## 2. 目标用户及痛点

**面向用户：** 所有使用 AI 编程助手（TRAE、Cursor、Copilot 等）进行项目开发的开发者，尤其是经常在多个工具和账号间切换、重视数据主权的人。

**使用场景：** 项目开发全生命周期——多轮对话之间传递上下文、多人协作时传递项目历史、工具切换时保持记忆连续、项目交接时完整交付知识。

**当前痛点：**

- **对话失忆**：新开对话 AI 不知道之前做了什么，重复探索已解决的问题，浪费算力和时间
- **工具锁定**：Claude Code 的 CLAUDE.md 只在 Claude Code 内有效，换工具记忆归零
- **平台风险**：海外工具政策不确定，近期 Claude Code 被曝植入针对中国用户的检测代码，记忆托管给单一平台存在不可控风险
- **维护负担**：Notion、Confluence 等文档工具需要手动维护，跟不上开发节奏
- **协作断裂**：换协作者时上下文丢失，新人不知道之前的决策和踩坑

## 3. 价值与意义

**效率价值：** 消除 AI 重复探索的算力浪费。对话结束时自动提取六维记忆（任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息），新对话开局 AI 先读记忆文件，直接跳过已验证的结论。仅"避免重复踩坑"一项就能在复杂项目中显著减少无效对话轮次。

**战略价值：** 在 AI 工具快速迭代、平台政策不确定的环境下，为开发者提供一个稳定的、可移植的、不受外部因素影响的记忆资产层。记忆归项目所有，不归任何平台。Markdown 是二十年不过时的格式，Git 是开发者最熟悉的版本管理工具——两者结合，确保记忆资产的长期可用性。

**生态价值：** 作为 TRAE Skill 实现，天然适配 TRAE 生态，但又不限于 TRAE。这种"工具兼容但不绑定"的设计，使其有潜力成为跨平台的开发记忆标准。

## 1. Demo 简介

dev-memory 是一个 TRAE Skill 技能，在对话结束时自动提取六维开发记忆，以纯 Markdown 文件形式保存在项目目录内。

- **是什么**：TRAE Skill 技能（一个 SKILL.md 文件，纯指令驱动，零脚本依赖）
- **面向谁**：所有使用 AI 编程助手的开发者
- **核心功能**：
  1. 六维记忆自动提取（任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息）
  2. 追加式演进（旧记忆不删除，新认知以更正记录形式追加，类似 Git 的版本管理思路）
  3. 按周自动归档（主文件保持精简，溢出条目按 ISO 周数归档）
  4. 自我进化（Skill 自身带迭代记录区域，每次执行后自动检查改进点）

## 2. Demo 创作思路

灵感来自实际开发中的痛点：用 AI 助手开发项目时，每轮对话积累的知识随对话结束而蒸发。现有记忆方案要么绑账号（ChatGPT Memory）、要么绑工具（Claude Code CLAUDE.md）、要么绑框架（Hermes Agent），但工具会换、账号会变，唯独项目和设备是稳定的。

特别值得注意的是，Claude Code 近期被曝出在代码中植入针对中国用户的隐蔽检测逻辑，这让把记忆托管给单一海外平台变得有风险。dev-memory 的定位是：记忆归项目所有，存在本地，不经过任何第三方。取 Claude Code 的"项目目录存储 + 自动维护"，取 Hermes 的"自我进化 + 迭代记录"，用纯 Markdown 实现，不绑任何工具。
