## 1. Demo 简介

**dev-memory v3.1 — 项目级 AI 记忆系统**

用 AI 编程助手开发项目时，每轮对话都在积累隐性知识：踩过的坑、验证过的方案、做过的架构取舍。但这些知识跟着对话上下文一起蒸发了——下次开新对话，AI 又从零开始，把走过的路重走一遍，把踩过的坑再踩一遍。

dev-memory 做的事很简单：把开发记忆的归属权从账号和工具上拿下来，放到项目这一层。用纯 Markdown + JSONL 文件存在项目目录里，跟着 Git 走，不绑任何平台。任何 AI 工具来了都能读，工具换了记忆还在。

- **是什么**：dev-memory v3.1 — 项目级 AI 记忆系统，纯 Markdown + JSONL 零依赖，寄生式注入 9+ 个 AI 编程工具（TRAE / Claude Code / Cursor / Copilot / Windsurf / Cline / CodeBuddy / Codex / Qwen Code 等），一个 SKILL.md 文件就是全部执行规范，零脚本、零依赖、零外部服务
- **面向谁**：所有使用 AI 编程助手的开发者，尤其是经常在多个工具和账号间切换、重视数据主权的人

- **核心功能**：
  1. **三层混合分层**：项目级索引（DEV_MEMORY.md，策展层）+ 会话级摘要（sessions/YYYY-MM-DD.md，导航层）+ 消息级 JSONL（sessions/YYYY-MM-DD.jsonl，原始层）。横向补充 USER_PROFILE.md（跨会话用户画像 + 贡献者溯源）和 CONFIG.md（配置 + 工具注入指引），完整保留开发过程
  2. **寄生式注入**：触发规则以"薄 Rule"形式注入到各编程工具（TRAE / Claude Code / Cursor / Codex / Windsurf / Cline / Copilot 等）的最高优先级层（Rules / CLAUDE.md / .cursor/rules / AGENTS.md / .windsurf/rules / .clinerules / copilot-instructions.md），厚 Skill（SKILL.md）按需加载完整执行流程。调研确认 Skill 在所有工具中优先级最低，注入到最高优先级层可确保每轮自动触发
  3. **六维记忆提取**：任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息——对话结束或任务完成时自动提取，不依赖用户说特定的话
  4. **自动关联检测**（v3.0）：Step 4 对比检查时自动检测新条目与已有条目的关键词重合度（≥2 个关键名词匹配），自动递增引用计数并追加交叉关联标记，使知识网络自然形成
  5. **记忆缺口检测**（v3.1）：开头检查 Step 10 检测 JSONL 最后一条时间戳与代码文件 mtime 的差距，自动发现跨会话隔离导致的记忆遗漏，即使宿主 AI 触发规则未生效也能兜底补录
  6. **19 条核心原则、10 步开头检查、7.5 步执行流程**：从 v1.0 的 6 步流程演进到 v3.1 的完整体系，每一项原则都来自实战踩坑后的改进
  7. **时序感知**（v2.1）：`[有效期:]` 标记 + `[~⏰]` 过期检测 + Dream 异步整理，纯文件方式实现轻量时序推理，借鉴 Zep/Graphiti 时序知识图谱和 ChatGPT V3 自动更新过期记忆的能力
  8. **版本迁移**（v3.0）：v1.x 旧格式项目自动检测 + 迁移指南（路径 / 格式 / 补建文件 / 触发规则验证 / 首次 Dream / 新对话建议），迁移不删除旧记忆，只追加格式标记

## 2. Demo 创作思路

**灵感来源**

在开发项目时发现一个很具体的痛点：用 AI 助手开发项目时，前一轮对话花了大量时间排查某个第三方 API 的参数问题，终于调通。结果下一轮新对话，AI 又从头试错。那一刻意识到，AI 缺的不是能力，是记忆。

AI 行业发展至今，记忆系统并不新鲜，但所有方案都绑在特定载体上：

- **ChatGPT 的 Memory** 绑用户账号——账号换了记忆没了
- **Claude Code 的 CLAUDE.md** 绑工具——换工具记忆归零
- **Hermes Agent 的四层记忆** 绑框架——需要完整框架支撑，太重

可现实是，AI 产品迭代极快，工具会换、账号会变，唯独你的设备和项目代码是稳定的锚点。

**特别值得注意的风险**

Claude Code 近期被曝出在代码中植入针对中国用户的隐蔽检测逻辑，这让把开发记忆托管给单一海外平台变得有风险。dev-memory 的定位是：记忆归项目所有，存在本地，不经过任何第三方。取 Claude Code 的"项目目录存储 + AI 自动维护"，取 Hermes 的"自我进化 + 迭代记录"，用纯 Markdown + JSONL 实现，不绑任何工具。

**想解决的问题**

AI 编程助手的"对话失忆"问题——新开对话 AI 不知道之前做了什么，重复探索已解决的问题，浪费算力和时间。让开发记忆成为随项目走的轻量资产，而非随账号或工具消散的临时数据。

**为什么做这个方向**

项目和设备是开发者最稳定的锚点，记忆应归属项目而非平台。Markdown 是二十年不过时的格式，Git 是开发者最熟悉的版本管理工具——两者结合，确保记忆资产的长期可用性。dev-memory 填补了 AI 记忆系统缺失的一环：已有针对"用户"的记忆系统（ChatGPT Memory），已有针对"Agent 工具"的记忆系统（Claude Code CLAUDE.md、Hermes Agent），但缺少针对"项目和设备"的记忆系统。

## 4. TRAE 实践过程

以下是用 TRAE 完成 dev-memory 开发的完整流程：

### Step 1：在 TRAE 中描述 dev-memory 设计需求，AI 生成 SKILL.md 技能文件

在 TRAE IDE 中打开新项目，向 AI 描述需求："我需要一个项目级 AI 记忆系统，在对话结束时自动提取六维开发记忆（任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息），以纯 Markdown 文件形式保存在项目目录内。" TRAE 的 AI 根据需求生成了初版 SKILL.md 技能文件，包含六维记忆提取、追加式演进、按周归档等核心机制。这是 dev-memory v1.0 的起点。

### Step 2：寄生式注入 TRAE 记忆系统

v2.0 架构升级时，发现 Skill 在 TRAE 中优先级最低，不保证触发。于是设计了寄生式注入方案：将触发规则以"薄 Rule"形式注入 TRAE 的 project_memory.md（3 条强制规则 + 3 条架构说明），同时在 user_profile.md 中注入全局触发偏好。薄 Rule 只写"何时触发 + 触发什么"，厚 Skill（SKILL.md）写完整执行规范。验证了三层混合分层架构（项目级 + 会话级 + 消息级 JSONL）在 TRAE 中的完整工作流。

### Step 3：创建 9 个工具适配器

为了实现"工具兼容但不绑定"的设计理念，在 TRAE 中创建了 9 个工具适配器文件（adapters/ 目录），覆盖 10+ 个主流 AI 编程工具：
- TRAE（project_rules 注入）
- Claude Code（CLAUDE.md 注入）
- Cursor（.cursor/rules/dev-memory.mdc 注入）
- GitHub Copilot（.github/copilot-instructions.md 注入）
- Windsurf（.windsurf/rules/dev-memory.md 注入）
- Cline（.clinerules 注入）
- CodeBuddy（.codebuddy/rules/dev-memory.md 注入）
- Codex / OpenCode / MiMoCode / Qwen Code（AGENTS.md 跨工具统一入口）
- 通用工具（自定义指令）

v2.2 时将所有 9 个适配器触发规则统一升级到 v2.2 标准（开头检查强化 + 时效扫描 + Dream 摘要 + 条件触发 + JSONL 即时追加 + 显式遗忘），确保跨工具一致性。

### Step 4：在 github-trending 项目中实战验证

在 github-trending 项目（GitHub 趋势看板）中实战验证 dev-memory，这是一个真实的数据分析项目，包含 API 对接、数据管道、可视化看板等完整功能。验证过程覆盖了 v1.0 → v3.0 的完整迁移：
- 路径迁移（docs/dev-memory/ → dev-memory/）
- 格式迁移（18 条记忆添加指纹 + 引用计数 + 价值标记 + 有效期 + 关联标记）
- 补建文件（CONFIG.md + sessions/ + USER_PROFILE.md）
- 触发规则验证（发现并修复 TRAE project_memory.md 中多项目路径未明确化的问题）
- 首次 Dream 整理

在实战中发现了关键的触发可靠性问题：迁移后 5 个 bug 修复未被记忆系统捕获，根因是宿主 AI 在对话开始时加载触发规则、运行中不会动态重读。这一发现直接推动了 v3.1 记忆缺口检测机制的诞生。

### Step 5：迭代优化 v2.0 → v3.1

在 TRAE 中持续迭代优化，每个版本都来自实战踩坑后的改进：

- **v2.0**：三层混合分层 + 寄生式注入 + USER_PROFILE.md（贡献者日志 + 设备溯源）+ 取消周归档 + 7.5 步流程
- **v2.1**：时序感知（有效期标记 + 过期检测）+ 异步 Dream（dream.md 输出）+ 记忆摘要页（health-report.md 健康度仪表盘）
- **v2.2**：条件触发（CONFIG.md 路径映射表）+ 模块化文件（@dimensions/ 引用语法）+ AGENTS.md 跨工具统一适配 + 显式遗忘（archived.jsonl）
- **v3.0**：自动关联检测（关键词匹配自动递增引用计数 + 交叉关联标记）+ 评估指标增强 + 版本迁移（v1.x → v3.0 迁移指南）
- **v3.1**：记忆缺口检测（Step 10 JSONL 时间戳 vs 代码 mtime）+ 跨会话隔离限制说明 + 迁移后新对话建议 + Step 5.5 合规自检清单 + 部分执行陷阱

每次迭代都在真实项目中验证，发现的问题反哺到 SKILL.md 的原则和流程中。例如 str.replace 静默失败导致状态概览连续 3 轮未更新成功，这一教训被写入迁移陷阱章节。

### Step 6：创建交互式 Demo HTML

在 TRAE 中创建交互式 Demo HTML，模拟完整的对话结束 → 记忆提取全过程。Demo 包含六维记忆提取可视化、三层架构交互图解、寄生式注入多工具适配演示、版本演进时间线、自动关联检测和记忆缺口检测原理动画等模块，让评审和用户直观理解 dev-memory 的工作原理。
