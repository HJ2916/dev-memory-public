### 4. 最终结论与最佳实践

- [2026-07-10 19:15] [★★★] Claude Code autoDream 三操作(合并/去重/提升)可在 dev-memory 中内联实现，不需要 daemon 常驻，成本仅 ~1300 token/次（约每周一次）
- [2026-07-10 19:00] [★★] Skill 与记忆文件分离更利于传播：CONFIG.md(~1KB)替代完整SKILL.md内嵌，用户有下载地址即可安装，adapters/目录覆盖10个工具
- [2026-07-10 18:30] [★★★] 分诊+增量写入的节省足以覆盖双触发的成本：G 省掉 50%+ 低价值对话的完整执行(每次省 ~8000 token)，I 降低 40% 写入成本，A+B 增加成本仅 ~700 token/对话。优化后整体 token 消耗净降
- [2026-07-10 18:10] [★★] 自动保存类 skill 的触发机制必须是"强制性"的（基于客观事件），不能是"建议性"的（依赖用户说特定的话）。任务完成和话题切换是最可靠的硬触发点
- [2026-07-10 18:05] 多项目识别功能是 dev-memory 的关键差异化：实际开发中一个 workspace 经常有多个项目，一次会话可能跨项目，机械写入当前目录会导致记忆遗漏
- [2026-07-10 17:30] 参赛定位核心叙事线：AI记忆已有用户级(ChatGPT)和Agent级(Claude Code/Hermes)，缺项目级；只有项目和设备才是开发者真正拥有的稳定资产
- [2026-07-10 17:05] Windows 环境下 git push GitHub 需同时配置 http.proxy 和 https.proxy，且需设置环境变量 ALL_PROXY
- [2026-07-10 17:00] gh CLI 可通过 winget 一键安装：`winget install --id GitHub.cli`
- [2026-07-10 16:50] `gh repo create <name> --private --source . --push` 可一步完成仓库创建、远程关联和代码推送

### 5. 架构决策记录

- [2026-07-10 19:10] [★★★] Skill 分离而非内嵌：CONFIG.md(~1KB)放项目内，SKILL.md通过下载安装 → 原因: 用户反馈"skill部署很快有下载地址即可"，分离更利于传播；多工具适配比内嵌更有价值
- [2026-07-10 19:00] [★★★] 隐私感知Git策略：记忆文件默认gitignore，公开仓库忽略/私有仓库建议追踪 → 原因: 开发者可能不想公开内部决策和踩坑细节，给引导也给选择
- [2026-07-10 18:20] [★★★] v1.2 方案选择: 采纳 11 项改进(A+B+C+G+H+I+D+E+J+L+M)，放弃 F(中间检查) → 原因: F 的增量收益仅 20% 但增量成本是 A+B 的数倍；G+I 的节省足以覆盖 A+B 的成本，净效果为 token 消耗净降
- [2026-07-10 18:05] 多项目识别用"线索优先级"而非自动推断：文件路径>项目名称>代码特征>已有记忆>当前目录 → 原因: 精确度递减，高优先级线索可靠，低优先级兜底
- [2026-07-10 17:30] 参赛文件与项目代码分离存放：competition/ 目录独立于核心代码 → 原因: 参赛材料是临时性的，项目代码是长期资产，分离便于后续管理
- [2026-07-10 17:00] GitHub 仓库设为私密 → 原因: 参赛要求作品不得在公开平台展示参赛成品形态，初赛时可附链接供评审查看
