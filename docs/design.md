## 1. 背景与目标

### 1.1 问题
TRAE 内置的 memory 系统（`c:\Users\JacobWu\.trae-cn\memory`）是工具级记忆，换工具后丢失。项目开发中积累的实现过程、思考路径、踩坑经验、最终结论等知识无法随项目带走，导致换工具后需重新探索，浪费算力。

### 1.2 目标
构建一个通用 skill，在每次对话结束时自动提取六维开发记忆，以纯 Markdown 文件形式保存在项目目录内，随代码版本管理。旧记忆保留不删，新记忆以时间戳标注，对旧记忆中的错误/矛盾/过时之处进行更正和澄清。整个 skill 本身也能自我进化。

### 1.3 设计原则
- **追加式演进**：旧记忆永不删除，只追加更正说明
- **零依赖**：纯 Markdown + 指令驱动，无脚本依赖，换任何工具都能读
- **自我进化**：skill 自身预留迭代记录区域，执行中发现不足时自动改进
- **时间精确**：所有时间戳精确到分钟（`YYYY-MM-DD HH:MM`）

## 4. 归档文件与自动归档机制

### 4.1 归档文件命名
`archive/YYYY-Www.md`（ISO周数，如 `2026-W28.md`）

### 4.2 归档文件结构
```markdown
# 开发记忆归档 - 2026年第28周 (07-07 ~ 07-13)

## 六维记忆全文

### 1. 任务与变更摘要
（本周所有条目，不截断）

### 2. 踩坑记录
（本周所有条目）

### 3. 探索路径
（本周所有条目）

### 4. 最终结论与最佳实践
（本周所有条目）

### 5. 架构决策记录
（本周所有条目）

### 6. 环境与依赖信息
（本周所有条目）

## 历史更正记录
（本周产生的更正）
```

### 4.3 自动归档触发规则
- 每次 dev-memory 执行时，先检查主文件中各维度的条目数
- 任务摘要/踩坑超过5条、探索路径/架构决策超过3条时，将溢出的旧条目移入当周归档文件
- 如果当周归档文件不存在，自动创建
- 归档文件中条目不截断，完整保留

### 4.4 跨周处理
如果当前日期已跨入新的一周（如周一执行时发现上周归档未完成），先将上周的溢出条目归档到上周文件，再处理本周。

## 5. SKILL.md 核心指令流程

### 5.1 触发时机
对话即将结束时（用户表达了结束意图，或任务完成后的自然收尾点），AI 自动执行。

### 5.2 执行流程（6步）

#### Step 1: 读取现有记忆
- 读取 `项目/docs/dev-memory/DEV_MEMORY.md`（如不存在则跳到 Step 2 初始化）
- 读取 SKILL.md 中的"迭代记录"区域（用于自我进化）

#### Step 2: 提取本次会话六维记忆
从对话上下文中提取：
1. **任务摘要** — 本次做了什么（1-3句话）
2. **踩坑记录** — 遇到什么错误、根因、修复方式
3. **探索路径** — 尝试了什么方案、为什么放弃/采纳
4. **最终结论** — 当前验证有效的最佳实践
5. **架构决策** — 为什么选这个方案、放弃什么
6. **环境信息** — 工具版本、API变更、配置变更

每条以 `[YYYY-MM-DD HH:MM]` 时间戳开头。

#### Step 3: 对比检查 — 更正与澄清
逐条将新记忆与主文件现有记忆对比：
- 发现矛盾 → 在"历史更正记录"中追加，保留原文 + 更正说明
- 发现过时 → 在"历史更正记录"中标注 `[YYYY-MM-DD HH:MM 过时]`
- 发现错误 → 在"历史更正记录"中追加更正

旧记忆本身不修改，只追加更正说明。

#### Step 4: 写入主文件
- 将新条目插入到各维度区块的顶部（最新在上）
- 更新顶部 metadata（最后更新时间、会话ID、周归档标识）
- 更新"当前状态概览"（用2-3句话概括最新进展）

#### Step 5: 溢出归档
- 检查各维度条目数是否超过上限（摘要/踩坑5条、探索/决策3条）
- 超出的旧条目移入 `archive/YYYY-Www.md` 对应区块
- 跨周时先归档上周溢出

#### Step 6: 自我进化检查
回顾本次执行过程中是否遇到以下情况：
- a) 某个维度不够用，需要增加新维度
- b) 归档逻辑有边界情况未覆盖
- c) 提取规则不够清晰导致遗漏

如有，在 SKILL.md 的"迭代记录"区域追加改进说明。如无，跳过。

### 5.3 关键约束
- 纯 Markdown 操作，不执行任何脚本
- 所有时间戳精确到分钟（`YYYY-MM-DD HH:MM`）
- 旧记忆永不删除，只追加更正
- 如果项目没有 `docs/dev-memory/` 目录，自动创建

## 6. 自我进化机制

### 6.1 迭代记录区域
SKILL.md 底部预留 `## 迭代记录` 区域：

```markdown
## 迭代记录

> 此区域记录 dev-memory skill 自身的改进历程。
> 每次执行 Step 6 自我进化检查时，如发现改进点则追加于此。

### v1.0 — 初始版本 [2026-07-10 17:15]
- 六维记忆提取：任务摘要、踩坑记录、探索路径、最终结论、架构决策、环境信息
- 主文件 + 按周归档机制
- 追加式更正，旧记忆不删除
- 触发时机：对话结束时自动执行

### [YYYY-MM-DD HH:MM] 改进说明
- 改进内容：...
- 触发原因：执行时遇到什么情况
- 影响范围：...
```

### 6.2 进化规则
- 只有在执行过程中真正发现不足时才追加改进记录
- 改进记录同样遵循"追加不删除"原则
- 每次改进标注版本号（v1.0 → v1.1 → v1.2...），小版本递增
- 如果改进涉及指令变更，直接在 SKILL.md 对应位置修改指令文本，同时在迭代记录中说明改了什么

### 6.3 可进化的维度
- 新增记忆维度（如发现六维不够）
- 调整归档阈值（如5条不够改10条）
- 优化提取规则（如某类信息经常遗漏）
- 修正触发逻辑（如发现某些场景需要特殊处理）
